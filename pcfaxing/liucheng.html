PC游戏发行平台全链路业务流程说明

帮助产品、研发、运营和QA理解从开发者创建游戏，到玩家购买、下载、启动的业务流程、系统协作、审核节点和ID流转。

流程目录

流程1 创建并审核游戏和DLC生成AppID并完成资料审核 流程2 准备游戏包和商品文件线与商品线并行 流程3 提交并执行正式上线发布审核和正式Build切换 流程4 玩家购买并下载订单、License和CDN下载 流程5 启动游戏并验权在线Ticket、7天离线许可和DLC使用权 关键关系说明Package、Depot和Build如何关联

应用与文件名词
Base App / 游戏本体
可安装和启动的游戏主体。开发者创建资料，平台生成AppID。示例：Neon Frontier，AppID＝app_2001
DLC App
归属于游戏本体的附加内容。每个DLC拥有独立DLC AppID。示例：剧情DLC 1，DLC AppID＝app_2101，归属app_2001
AppID
游戏本体或DLC的唯一应用编号，由平台系统生成，开发者不能自行填写。示例：游戏本体app_2001；DLC app_2101
Depot
一组一起下载的文件，可按游戏本体、DLC、Windows、macOS或语言拆分。示例：depot_2001_win＝本体Windows文件；depot_2101_all＝DLC文件
Upload ID
一次上传任务的编号，暂停和续传继续使用同一个Upload ID。示例：upl_20260907_001
Build
一次不可修改的游戏文件版本。修复文件必须创建新的Build ID。示例：bld_3200＝Neon Frontier 1.5.0文件版本
Manifest
Build包含哪些文件和分块的清单，记录路径、大小和Hash。示例：manifest_win_3200描述bld_3200中的Windows文件
商品与使用权名词
Package
一个可销售或激活的授权单元。游戏本体和每个DLC通常分别配置Package。示例：pkg_base_2001授予app_2001；pkg_dlc_2101授予app_2101
Bundle
多个Package的组合，例如豪华版＝游戏本体Package＋DLC Package。示例：bundle_deluxe_2001＝pkg_base_2001＋pkg_dlc_2101
价格版本
开发者每次提交审核的价格快照。新版本通过前，旧价格继续生效。示例：price_v3＝全部地区USD 29.99
Order / 订单
玩家购买时生成的交易记录，保存购买内容和当时价格。示例：order_88001购买bundle_deluxe_2001
License / 使用权
玩家购买后由系统写入账号的持有记录，决定能否下载和使用游戏或DLC。示例：lic_99001把pkg_base_2001授予usr_100086
发布、下载与启动名词
Release / 上线申请
把某个Build设置到指定环境的一次发布申请和执行记录。示例：rel_33001把bld_3200发布到Production
Branch / 环境
决定一类用户使用哪个Build，例如Production正式环境、Internal测试环境。示例：Production给正式玩家；Internal给QA测试账号
Active Build
某个环境当前实际向用户提供的Build。示例：app_2001的Production当前指向bld_3200
CDN
向玩家就近分发游戏文件。CDN只验证短期下载凭证，不判断商品价格。示例：授权后分发manifest_win_3200对应的Chunk
下载授权
平台确认玩家有License且Build可下载后生成的短期访问凭证。示例：da_77001，只允许下载bld_3200且10分钟后过期
Launch Ticket
客户端启动游戏时申请的一次性短期凭证，用于证明合法启动。示例：lt_55001，绑定usr_100086、app_2001和bld_3200
Offline License
设备联网验权成功后获得的签名许可，允许匹配账号、游戏和设备在168小时内离线启动。联网并成功复核后续期；网络连通本身不续期
Session ID
SDK验权成功后创建的游戏会话编号。示例：sess_66001
SDK
游戏接入平台账号、启动和DLC使用权验证的一套接口。示例：PlatformSDK_Init("app_2001")

关键关系：Package ID和Build ID如何关联？

两者有关系，但不直接一对一绑定。Package决定玩家有权访问哪些Depot；Build决定这些Depot当前使用哪份Manifest。二者通过Depot ID关联。

不要保存“Build ID直接等于某个Package ID”同一个游戏文件可能被标准版和豪华版共同使用；修改价格不应重新生成Build，更新Build也不应修改全部Package。
