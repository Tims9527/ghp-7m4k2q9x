PC游戏发行平台全链路业务流程说明

帮助产品、研发、运营和QA理解从开发者创建游戏，到玩家购买、下载、启动的业务流程、系统协作、审核节点和ID流转。

流程目录

流程1 创建并审核游戏和DLC生成AppID并完成资料审核 流程2 准备游戏包和商品文件线与商品线并行 流程3 提交并执行正式上线发布审核和正式Build切换 流程4 玩家购买并下载订单、License和CDN下载 流程5 启动游戏并验权SDK、Ticket和DLC使用权

  • 每个节点标明角色和操作入口。
  • 蓝色表示系统自动处理。

应用与文件名词
Base App / 游戏本体
可安装和启动的游戏主体。开发者创建资料，平台生成AppID。
DLC App
归属于游戏本体的附加内容。每个DLC拥有独立DLC AppID。
AppID
游戏本体或DLC的唯一应用编号，由平台系统生成，开发者不能自行填写。
Depot
一组一起下载的文件，可按游戏本体、DLC、Windows、macOS或语言拆分。
Upload ID
一次上传任务的编号，暂停和续传继续使用同一个Upload ID。
Build
一次不可修改的游戏文件版本。修复文件必须创建新的Build ID。
Manifest
Build包含哪些文件和分块的清单，记录路径、大小和Hash。
商品与使用权名词
Package
一个可销售或激活的授权单元。游戏本体和每个DLC通常分别配置Package。
Bundle
多个Package的组合，例如豪华版＝游戏本体Package＋DLC Package。
价格版本
开发者每次提交审核的价格快照。新版本通过前，旧价格继续生效。
Order / 订单
玩家购买时生成的交易记录，保存购买内容和当时价格。
License / 使用权
玩家购买后由系统写入账号的持有记录，决定能否下载和使用游戏或DLC。
发布、下载与启动名词
Release / 上线申请
把某个Build设置到指定环境的一次发布申请和执行记录。
Branch / 环境
决定一类用户使用哪个Build，例如Production正式环境、Internal测试环境。
Active Build
某个环境当前实际向用户提供的Build。
CDN
向玩家就近分发游戏文件。CDN只验证短期下载凭证，不判断商品价格。
下载授权
平台确认玩家有License且Build可下载后生成的短期访问凭证。
Launch Ticket
客户端启动游戏时申请的一次性短期凭证，用于证明合法启动。
Session ID
SDK验权成功后创建的游戏会话编号。
SDK
游戏接入平台账号、启动和DLC使用权验证的一套接口。

1

创建并审核游戏和DLC

从开发者账号开始，终点是应用资料审核通过。

流程起点：开发者已经开通平台账号开发者组织和操作权限已经配置完成
角色：开发者管理员入口：开发者开放平台 → 游戏管理

创建游戏本体；需要DLC时创建DLC

填写游戏名称、支持系统、发行资料；每个DLC单独填写资料并归属游戏本体。

↓
角色：平台系统系统：应用目录服务

生成应用编号并建立归属关系

游戏本体和每个DLC分别获得唯一编号；平台初始化空白默认销售项，后续由开发者配置。

输出：游戏AppID、DLC AppID、默认Package ID

↓
角色：运营审核入口：运营管理后台 → 游戏/DLC审核

审核游戏和DLC资料

检查开发者资质、发行材料、游戏名称和DLC归属。

游戏和DLC资料审核通过

2

准备游戏包和商品

两条工作并行，全部完成后才能首次上线。

流程起点：游戏和DLC资料审核通过来自流程1终点
下面两条线可以同时进行，不要求先做完其中一条。

A. 准备游戏包

决定玩家要下载的实际文件。

角色：开发者构建人员入口：开发者开放平台 → Depot与构建

创建文件仓库

选择游戏本体或DLC，配置Windows/macOS、架构和语言。

输出：Depot ID

↓
角色：开发者构建人员入口：本地上传组件

扫描并上传游戏文件

计算Hash和分块，复用已有文件，只上传缺失内容，支持暂停和续传。

输出：Upload ID、候选Build ID

↓
角色：平台系统系统：构建服务、对象存储

重建、检查并生成游戏包

检查病毒、路径、权限、启动程序和系统签名，生成不可修改的文件清单。

输出：Manifest ID、最终Build ID

↓
角色：QA入口：PC客户端测试账号 + 运营后台包体测试

下载安装并测试

测试安装、更新、启动和游戏功能，提交测试结论。

输出：QA测试记录ID

↓
角色：运营审核入口：运营管理后台 → 提包审核

审核测试通过的游戏包

↓
失败或不通过

开发者上传修复Build

返回上传步骤，创建新Build。

通过

Build可以发布

B. 准备商品

决定玩家买到什么、支付多少钱。

角色：开发者管理员入口：开发者开放平台 → Package、Bundle与定价

配置游戏本体和DLC销售项

填写销售内容、全部地区美元价格和销售说明。

使用：默认Package ID；也可新建附加Package ID

↓
角色：开发者管理员入口：同一商品页面

按需创建豪华版或旗舰版

选择两个或更多已配置销售项组成组合版本。

输出：Bundle ID

↓
角色：平台系统系统：商品与定价服务

冻结本次商品申请

审核期间不允许修改本次提交内容。

输出：Package版本ID、价格版本ID、Bundle版本ID

↓
角色：运营审核入口：运营管理后台 → Package定价审核 / Bundle审核

3

提交并执行正式上线

决定哪个游戏包在哪个环境、什么时间生效。

流程起点：Build可以发布＋商品获得销售资格来自流程2终点；以后只更新Build时，已经生效的商品不需要重新审核。
角色：开发者管理员入口：开发者开放平台 → 发布管理

提交上线申请

选择Build、正式/测试环境，以及立即上线或定时上线。

↓
角色：平台系统系统：发布服务

保存上线申请并创建审核任务

输出：Release ID、发布审核任务ID

↓
角色：运营审核入口：运营管理后台 → 发布审核

审核Build、环境和上线时间

↓

↓

5

启动游戏并完成SDK验权

确认文件正确、启动凭证有效、玩家拥有游戏和DLC。

流程起点：游戏已安装且文件校验通过来自流程4终点
角色：玩家入口：PC客户端 → 游戏详情

选择需要启用的DLC并点击启动

↓
