完整 BUILD 模型 · 演示说明

从创建游戏到玩家获得正式版本

开发者端负责创建业务对象并提交；运营后台负责测试、审核和执行；系统只在Release执行成功后切换Active Build。

文件归属App → Depot
文件快照Depot → Manifest
完整版本Build → 多个Manifest
发布动作Release → Build + Branch
线上指针App + Branch → Active Build

二、实际演示操作路径

建议技术按以下顺序打开页面，并用Release ID、Build ID、AppID和Branch核对两端记录。

开发者端

  1. 选择游戏进入单游戏工作台。
  2. 进入“游戏包管理 → Depot管理”。
  3. 进入“构建管理”，查看默认已通过完整Build，或自行创建Build。
  4. 进入“发布管理与记录”。
  5. 点击“提交发布申请”，选择Build与Branch。
  6. 提交后状态为“审核已通过／待执行”。
打开开发者端演示

运营后台

  1. 进入“发布审核”，查看同一Release及Branch。
  2. 进入“发布任务管理”，找到状态“待执行”的Release。
  3. 点击“立即执行”。
  4. 进入“线上版本与回滚”。
  5. 确认相同App与Branch只有一个“当前版本”。
  6. 核对Active Build ID与刚执行的Release一致。
打开发布任务管理打开线上版本与回滚

三、关键状态变化

用状态变化判断操作是否真正生效。

动作BuildRelease审核发布任务Active Build玩家下载
创建并冻结BuildFROZEN——不变仍下载旧版本
QA与提包通过可发布——不变仍下载旧版本
提交Release不变默认通过待执行不变仍下载旧版本
发布任务执行成功不变已通过已上架切换到新Build获得新版本
发布任务失败或取消不变已通过失败／取消不变仍下载旧版本
回滚成功历史Build不变生成回滚记录执行成功切换到历史Build获得回滚版本

Branch位置：开发者在创建Release时选择；运营端在发布审核、发布任务管理和线上版本页面查看。Build与Depot页面不设置Branch。
